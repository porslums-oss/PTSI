PTSI Accounting — สรุปสิ่งที่ทำ วิธีการ และเครื่องมือ

สรุปการย้ายระบบบัญชี PTSI จาก Oracle APEX ไปเป็นเว็บแอปบน PostgreSQL (Neon) + Node.js (Vercel): แนวคิด ขั้นตอนที่ทำ วิธีการ เครื่องมือ และผลลัพธ์ที่ตรวจสอบได้

ระบบเดิม: Oracle APEX (WKSP_PTSI, App 151494)ระบบใหม่: Node.js + PostgreSQLฐานข้อมูล: 55 ตาราง · 9 view · 87 ฟังก์ชัน · 28 triggerAPI: ~120 endpointsอัปเดต: 2026-10-06

แนวคิดหลักDatabase-centric
คงแนวทาง “ตรรกะอยู่ในฐานข้อมูล” แบบเดียวกับที่ทำบน Oracle (PL/SQL → PL/pgSQL) เพื่อให้ผู้ดูแลที่ชำนาญ Oracle ตรวจและแก้ไขตรรกะบัญชีได้ในที่เดียว ส่วน Node.js ทำหน้าที่ตรวจสิทธิ์และส่งต่อคำขอเท่านั้น หน้าเว็บเป็นไฟล์เดียวไม่ต้อง build

ส่วนผลลัพธ์
ฐานข้อมูลschema acct: 55 ตาราง, 9 view, 87 ฟังก์ชัน (SECURITY DEFINER), 28 trigger (audit, period guard, ฯลฯ), 153 index, 48 sequence · role แยก 3 ระดับ (owner/app/report)
ธุรกิจฝั่งขายใบเสนอราคา → ใบส่งของ → ใบแจ้งหนี้ → ใบวางบิล → ใบเสร็จ → ใบลดหนี้ ลงบัญชีอัตโนมัติ
ธุรกิจฝั่งซื้อPR → PO → รับสินค้า → ใบแจ้งหนี้ผู้ขาย → จ่ายเงิน → 50 ทวิ → ใบลดหนี้ผู้ขาย
บัญชีCash Book, ทะเบียนผู้ถือหุ้น, GL (journal/ledger/TB/งบกำไรขาดทุน/งบฐานะ), ปิดงวด, รายงานภาษี (ภ.พ.30, ภ.ง.ด.3/53, อายุหนี้) พิมพ์/Excel
ผู้ใช้และสิทธิ์4 บทบาท × 8 สิทธิ์ แก้ได้ในหน้า Settings · Audit Log ของทุกการเพิ่ม/แก้/ลบ
ข้อมูลหลักลูกค้า ผู้ขาย ธนาคาร (อยู่ใน DB) สินค้า พนักงาน ผังบัญชี · ที่อยู่แบบเลือกจังหวัด→อำเภอ→ตำบล · นำเข้าข้อมูลจากไฟล์ด้วย AI
ประสบการณ์ใช้งานธีมม่วง/ทอง หน้า Login ใหม่, ปุ่มล้างข้อมูลทุกฟอร์ม, cache + prefetch ทำให้สลับเมนูเร็ว
เอกสารชุด 7 เอกสารนี้ + Excel data dictionary + SQL คอมเมนต์ตาราง/คอลัมน์

วิธีการที่ใช้Methods

วิธีการรายละเอียด
Database-centricทุกกติกาบัญชี (เลขที่เอกสาร, VAT, debit=credit, ปิดงวด, สถานะ) บังคับใน acct.fn_* และ trigger — เรียกจากทางใดก็ได้ผลเหมือนกัน
สคริปต์เป็นขั้นเรียงเลขทุกการเปลี่ยนแปลงเป็นไฟล์ neon_N_*.sql รันซ้ำได้ (CREATE OR REPLACE) — ตั้งแต่ neon_1 ถึง 21 เพื่อรันใน Neon SQL Editor ได้โดยไม่ต้องใช้เครื่องมือเสริม
Thin APIExpress ~120 endpoints แต่ละตัวเรียก 1 ฟังก์ชัน DB; ตรวจสิทธิ์ด้วย requiredPerm(); แปลง RAISE EXCEPTION 'CODE: …' เป็น HTTP status
Front-end ไฟล์เดียวHTML + vanilla JS ไม่มี build step — แก้ไฟล์เดียวแล้ว deploy; มี cache ฝั่งหน้าเว็บ + prefetch ข้อมูลหลัก + ตัวป้องกันการสลับหน้าซ้อน (navSeq)
Reconciliationทดสอบกับข้อมูลจริงที่ย้ายมา: เทียบจำนวนแถว ยอดรวม และ Trial Balance ก่อน–หลัง; เทียบ DDL กับสคริปต์ที่ติดตั้งใหม่
ทดสอบ end-to-endPlaywright ขับเบราว์เซอร์ผ่านเมนูจริง · ทดสอบ API ด้วยผู้ใช้ 4 บทบาท (ตรวจ 403) · ทดสอบกฎ เช่น PO_REQUIRED, OVER_APPLIED, PERIOD_CLOSED
การพัฒนาแบบวนรอบรับ feedback จากผู้ใช้ → แก้ → ส่งไฟล์ที่เปลี่ยน → อัปโหลด GitHub → Vercel deploy อัตโนมัติ
ตรวจติดตั้งใหม่สร้างฐานข้อมูลเปล่า ptsi_fresh จากสคริปต์ล้วน แล้วเทียบกับฐานทดสอบ จนได้ลำดับที่ถูกต้อง (บันทึกในเอกสาร 05)

ข้อจำกัดที่ทราบKnown limitations

  • !
    ไม่มีทะเบียนสินค้าคงคลัง/ต้นทุนขาย และไม่มีเอกสารรายการปรับปรุงสิ้นงวด (manual journal) บนหน้าจอ
  • !
    เลขที่เอกสารอาจไม่ต่อเนื่อง — ต้องยืนยันกับนักบัญชีสำหรับใบกำกับภาษี
  • !
    ไม่มี CI/ชุดทดสอบอัตโนมัติในรีโป — การทดสอบทำด้วยสคริปต์ชั่วคราว
  • !
    ยังไม่ได้ทดสอบโหลดหลายผู้ใช้ และขั้นตอนติดตั้ง Windows/macOS/Docker ยังไม่ได้ทดสอบบนเครื่องจริง

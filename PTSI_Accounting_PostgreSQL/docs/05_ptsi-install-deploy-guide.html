ติดตั้งบน Linux (Oracle Linux / RHEL / Ubuntu)Linux

ตัวอย่างทำบนบัญชี root/sudo — ชื่อแพ็กเกจต่างกันตามดิสโทร

4.1 ติดตั้ง PostgreSQL + Node.js

Ubuntu 22.04/24.04
sudo apt update
sudo apt install -y postgresql postgresql-contrib nginx curl
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v   # ต้อง >= v20
psql --version
Oracle Linux 8/9 / RHEL 8/9
sudo dnf install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-9-x86_64/pgdg-redhat-repo-latest.noarch.rpm
sudo dnf -qy module disable postgresql
sudo dnf install -y postgresql16-server postgresql16-contrib nginx
sudo /usr/pgsql-16/bin/postgresql-16-setup initdb
sudo systemctl enable --now postgresql-16
sudo dnf module enable -y nodejs:20 && sudo dnf install -y nodejs
# ถ้าใช้ EL-8 ให้เปลี่ยน EL-9 → EL-8 ในลิงก์ repo

ปรับ pg_hba.conf ให้ผู้ใช้แอปเชื่อมต่อด้วยรหัสผ่านจาก localhost (host ptsi_accounting acct_app 127.0.0.1/32 scram-sha-256) และอย่าเปิด listen_addresses ออกภายนอกถ้าไม่จำเป็น แล้ว systemctl reload postgresql

4.2 สร้างฐานข้อมูลและรันสคริปต์

bash
sudo -u postgres createdb -E UTF8 ptsi_accounting
cd /opt/ptsi-accounting/db/neon_editor     # หลังแตกซอร์สไว้ที่ /opt/ptsi-accounting
# 1) แก้รหัสผ่าน 3 ตัวใน neon_1_roles_schema.sql ก่อน
run() { sudo -u postgres psql -d ptsi_accounting -v ON_ERROR_STOP=1 -q -f "$1"; }
run neon_1_roles_schema.sql
run neon_2_functions.sql
run neon_3_views_seed.sql
for f in data_migration/0[1-7]_*.sql; do run "$f"; done
for n in $(seq 5 21); do run neon_${n}_*.sql; done
run neon_4_healthcheck.sql

สคริปต์ใช้ SET ROLE acct_owner ภายในไฟล์ จึงต้องรันด้วยผู้ใช้ที่เป็น superuser (เช่น postgres) หรือเจ้าของฐานข้อมูลที่สร้าง role ได้ — ถ้าไฟล์ใดล้มเหลว (ON_ERROR_STOP) ให้แก้แล้วรันไฟล์นั้นซ้ำ: ไฟล์ส่วนใหญ่เขียนแบบรันซ้ำได้ (CREATE OR REPLACE/IF NOT EXISTS) แต่ให้ตรวจกับ neon_4 ทุกครั้ง

4.4 ให้รันเป็นบริการ (systemd)

bash
sudo cp /opt/ptsi-accounting/deploy/ptsi-accounting.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ptsi-accounting
sudo systemctl status ptsi-accounting
journalctl -u ptsi-accounting -f      # ดู log

4.5 HTTPS ด้วย nginx

  1. วางใบรับรอง TLS ที่ /etc/nginx/ssl/ptsi-accounting.crt และ .key (ใช้ใบรับรององค์กร หรือ Let’s Encrypt)
  2. คัดลอก deploy/nginx-ptsi-accounting.conf ไป /etc/nginx/conf.d/ แล้วแก้ server_name
  3. sudo nginx -t && sudo systemctl reload nginx
  4. ตั้ง client_max_body_size ให้ ≥ 5m หากใช้ฟีเจอร์แนบไฟล์/นำเข้าไฟล์ (แอปรับไฟล์ได้ถึง 4 MB — ค่าในไฟล์ตัวอย่างคือ 2m จะทำให้อัปโหลดไฟล์ใหญ่ไม่ผ่าน)
  5. เปิดพอร์ต 443/80 บนไฟร์วอลล์ (firewall-cmd --add-service=https --permanent หรือ ufw allow 443) · SELinux (EL): setsebool -P httpd_can_network_connect 1

4.6 สำรองข้อมูลอัตโนมัติ

bash
# สร้าง ~/.pgpass ของ user ที่รัน (chmod 600)  localhost:5432:ptsi_accounting:acct_owner:<password>
sudo mkdir -p /backup/ptsi-accounting
sudo chmod +x /opt/ptsi-accounting/deploy/backup.sh
( crontab -l; echo "0 1 * * * /opt/ptsi-accounting/deploy/backup.sh >> /var/log/ptsi-backup.log 2>&1" ) | crontab -
# ทดสอบกู้คืนเป็นระยะ:  createdb ptsi_restore_test && pg_restore -d ptsi_restore_test /backup/ptsi-accounting/<ไฟล์>.dump

ติดตั้งบน Windows ServerWindows

ยังไม่ได้ทดสอบบนเครื่องจริง

  1. ติดตั้ง PostgreSQL 16 (ตัวติดตั้ง EDB — จำรหัสผ่าน postgres, port 5432) เลือก Stack Builder/pgAdmin ตามต้องการ
  2. ติดตั้ง Node.js 20 LTS (ตัวติดตั้ง .msi จาก nodejs.org) ตรวจด้วย node -v ใน PowerShell
  3. สร้างฐานข้อมูล: & "C:\Program Files\PostgreSQL\16\bin\createdb.exe" -U postgres -E UTF8 ptsi_accounting
  4. รันสคริปต์ด้วย psql ตามลำดับบทที่ 3 (ตัวอย่าง PowerShell ด้านล่าง)
  5. คัดลอกโฟลเดอร์ app ไป C:\ptsi-accounting\app · สร้างไฟล์ .env (ตามบทที่ 4.3 แต่ PGHOST=localhost) · รัน npm install --omit=dev
  6. ให้รันเป็น Windows Service: NSSM (nssm install PTSI-Accounting "C:\Program Files\nodejs\node.exe" server.js ตั้ง AppDirectory เป็นโฟลเดอร์ app) หรือ PM2 (npm i -g pm2 pm2-windows-startup; pm2 start server.js --name ptsi; pm2 save)
  7. HTTPS: ใช้ IIS + URL Rewrite/ARR ชี้ไป http://127.0.0.1:3001 หรือ nginx for Windows · เปิดไฟร์วอลล์พอร์ต 443
  8. สำรองข้อมูล: Task Scheduler รัน pg_dump.exe -U acct_owner -d ptsi_accounting -Fc -f D:\backup\ptsi_%date%.dump ทุกคืน (ตั้ง %APPDATA%\postgresql\pgpass.conf สำหรับรหัสผ่าน)
PowerShell — รันสคริปต์ DB
$env:PGPASSWORD="<postgres password>"
$psql="C:\Program Files\PostgreSQL\16\bin\psql.exe"
function Run($f){ & $psql -U postgres -d ptsi_accounting -v ON_ERROR_STOP=1 -q -f $f }
cd C:\ptsi-accounting\db\neon_editor
Run neon_1_roles_schema.sql; Run neon_2_functions.sql; Run neon_3_views_seed.sql
Get-ChildItem data_migration\0[1-7]_*.sql | Sort-Object Name | % { Run $_.FullName }
5..21 | % { Get-ChildItem "neon_$($_)_*.sql" | % { Run $_.FullName } }
Run neon_4_healthcheck.sql

ติดตั้งด้วย Docker (ทางเลือก)Docker

ซอร์สปัจจุบันยังไม่มี Dockerfile/compose — ตัวอย่างนี้เป็นแนวทางที่ต้องทดสอบก่อนใช้

Dockerfile (ตัวอย่าง)
FROM node:20-alpine
WORKDIR /app
COPY app/package*.json ./
RUN npm install --omit=dev
COPY app/ ./
ENV HTTP_HOST=0.0.0.0 HTTP_PORT=3001
USER node
EXPOSE 3001
CMD ["node","server.js"]
docker-compose.yml (ตัวอย่าง)
services:
  db:
    image: postgres:16
    environment: { POSTGRES_PASSWORD: change_me, POSTGRES_DB: ptsi_accounting }
    volumes: [ "pgdata:/var/lib/postgresql/data" ]
  app:
    build: .
    depends_on: [ db ]
    environment: { PGHOST: db, PGDATABASE: ptsi_accounting, PGUSER: acct_app, PGPASSWORD: "<app password>", PGSSL: "false" }
    ports: [ "127.0.0.1:3001:3001" ]
volumes: { pgdata: {} }

รันสคริปต์ฐานข้อมูลครั้งแรกด้วย docker compose exec -T db psql -U postgres -d ptsi_accounting -f - < file.sql ตามลำดับบทที่ 3

Deploy บน Vercel + Neon (ที่ใช้งานปัจจุบัน)Vercel + Neon

8.1 Neon (ฐานข้อมูล)

  1. สมัคร neon.tech สร้าง Project/Database ชื่อ ptsi_accounting (แนะนำ region ใกล้ผู้ใช้ เช่น Singapore)
  2. เปิด SQL Editor เลือกฐานข้อมูลนี้ แล้ววางและรันสคริปต์ตามลำดับในบทที่ 3 ทีละไฟล์ (รัน neon_1 หลังแก้รหัสผ่าน 3 ตัว)
  3. รัน neon_4_healthcheck.sql ตรวจจำนวนอ็อบเจกต์
  4. คัดลอก Connection string แบบ Pooled ของ role acct_app (รูปแบบ postgresql://acct_app:…@…-pooler….neon.tech/ptsi_accounting?sslmode=require)

8.2 GitHub

  1. สร้าง repository (private แนะนำ) แล้วอัปโหลดไฟล์ในโฟลเดอร์ app ไว้ที่ root ของ repo ได้แก่ server.js, config.js, package.json, vercel.json, .vercelignore, api/index.js, public/… (ห้ามอัปโหลด .env)
  2. แก้ไฟล์ภายหลัง: GitHub → Add file → Upload files (เขียนทับไฟล์เดิม) → Commit — Vercel จะ deploy ให้อัตโนมัติ

8.3 Vercel

  1. Import repository ใน Vercel (Framework = Other) — ไม่ต้องตั้ง build command
  2. ตั้ง Environment Variables ตามตารางด้านล่าง ครบทุก Environment (Production/Preview)
  3. กด Deploy และรอสถานะ Ready · หลังเปลี่ยน Environment Variable ต้อง Redeploy จึงมีผล
  4. เปิดเว็บ → เข้าสู่ระบบ admin → เปลี่ยนรหัสผ่านทันที (Settings → ผู้ใช้งาน)
  5. ล้างแคชเบราว์เซอร์ (Ctrl+F5) หลังอัปเดตหน้าเว็บ

อัปเกรด สำรอง และกู้คืนOperations

อัปเกรดแอป

  1. สำรองฐานข้อมูลก่อนเสมอ
  2. เปลี่ยนไฟล์ server.js/public/index.html (Cloud: อัปโหลด GitHub · On-prem: คัดลอกไฟล์แล้ว systemctl restart ptsi-accounting)
  3. หากมีสคริปต์ neon_NN ใหม่ ให้รันตามลำดับเลขบนฐานข้อมูลเดิม แล้วรัน neon_4 ตรวจ

กู้คืนฐานข้อมูล (On-premise)

bash
sudo systemctl stop ptsi-accounting
sudo -u postgres dropdb ptsi_accounting && sudo -u postgres createdb -E UTF8 ptsi_accounting
# role ต้องมีอยู่ (acct_owner/acct_app/acct_report) — สร้างผ่านบทที่ 3 ขั้นที่ 1 หรือ pg_dumpall --roles-only
sudo -u postgres pg_restore -d ptsi_accounting --no-owner --role=acct_owner /backup/ptsi-accounting/<ไฟล์>.dump
sudo systemctl start ptsi-accounting

Neon

ใช้ Branch/Point-in-time restore ของ Neon (ช่วงเวลาย้อนหลังขึ้นกับแพ็กเกจ) และควร pg_dump ออกมาเก็บภายนอกเป็นระยะ: pg_dump "$DATABASE_URL_OWNER" -Fc -f ptsi.dump

ความมั่นคงปลอดภัยSecurity & Access Control

รหัสความเสี่ยงผลกระทบระดับแนวทางป้องกัน
S1รหัสผ่านเริ่มต้นของ admin (ตั้งโดยสคริปต์ neon_3) เป็นค่าที่รู้กันทั่วไป หากติดตั้งใหม่แล้วไม่เปลี่ยนผู้ไม่หวังดีเข้าระบบด้วยสิทธิ์สูงสุดสูงเปลี่ยนรหัสผ่านทันทีหลัง deploy ทุกครั้ง · ตรวจในรายการ go-live · ทำสคริปต์/ขั้นตอนบังคับเปลี่ยนรหัสผ่านครั้งแรก
S2ไม่มีการจำกัดจำนวนครั้ง login ผิด / ล็อกบัญชี / นโยบายความซับซ้อนรหัสผ่าน (บังคับเพียงยาว ≥ 8 ตัวเมื่อสร้างผู้ใช้)ถูกเดาสุ่มรหัสผ่าน (brute force)สูงเพิ่ม rate limit ที่ API/WAF (เช่น Vercel Firewall) · ล็อกชั่วคราวหลังผิดหลายครั้ง · ใช้รหัสผ่านยาวและไม่ซ้ำ
S3Session token เก็บใน localStorage ของเบราว์เซอร์ — หากมีช่องโหว่ XSS โทเค็นถูกขโมยได้ถูกสวมสิทธิ์ผู้ใช้จนกว่า token หมดอายุ (12 ชม.)กลางโค้ดใช้ฟังก์ชัน escape (h()) กับข้อมูลที่แสดง · เพิ่ม Content-Security-Policy · ลดอายุ session · ย้ายไป HttpOnly cookie ในอนาคต
S4ยังไม่ตั้ง HTTP header ป้องกัน: ไม่มี CSP, HSTS (มีเฉพาะ nosniff, X-Frame-Options, Referrer-Policy)เสี่ยง XSS/downgrade มากขึ้นเล็กน้อยกลางเพิ่ม CSP/HSTS ใน server.js หรือ vercel.json (Vercel บังคับ HTTPS อยู่แล้ว) · On-prem: HSTS อยู่ในตัวอย่าง nginx
S5การเชื่อมต่อ Neon ตั้ง rejectUnauthorized:false (ไม่ตรวจใบรับรองเซิร์ฟเวอร์)เข้ารหัสแต่ไม่ยืนยันตัวตนปลายทาง — เสี่ยง MITM ในทางทฤษฎีต่ำตั้ง ssl เป็น verify-full พร้อม CA ที่เชื่อถือได้เมื่อทดสอบแล้ว
S6คีย์ลับ (DATABASE_URL, GEMINI/ANTHROPIC API KEY) อยู่ใน Environment Variables · ไฟล์ .env บนเซิร์ฟเวอร์รั่วไหลหากอัปโหลด .env ขึ้น GitHub หรือสิทธิ์ไฟล์หลวมสูงไม่ commit .env (มี .vercelignore) · repo เป็น private · chmod 600 · เปลี่ยนคีย์ทันทีเมื่อสงสัยรั่ว · จำกัดวงเงิน/สิทธิ์ของคีย์ AI
S7ฟีเจอร์ AI import ส่งไฟล์เอกสาร (ใบเสนอราคา/ใบกำกับภาษี/นามบัตร) ไปยังผู้ให้บริการภายนอก — แพ็กเกจฟรีของบางผู้ให้บริการอาจนำข้อมูลไปปรับปรุงโมเดลข้อมูลลูกค้า/ผู้ขายออกนอกองค์กร (PDPA)กลางใช้คีย์แบบชำระเงิน/ตั้งค่าไม่ใช้ข้อมูลฝึกโมเดล · แจ้งผู้ใช้ห้ามอัปโหลดเอกสารลับ · ปิดฟีเจอร์ได้โดยไม่ตั้ง KEY
S8สิทธิ์ถูกตรวจที่ API (requiredPerm) — endpoint ใหม่ที่ลืมใส่สิทธิ์จะเปิดให้ผู้ล็อกอินทุกบทบาทเพิ่มสิทธิ์โดยไม่ตั้งใจกลางทดสอบสิทธิ์รายบทบาทก่อนปล่อยเวอร์ชันใหม่ (ทำเป็น test script) · review ทุก route ที่เพิ่ม
2

ข้อมูลและการสำรองData & Backup

รหัสความเสี่ยงผลกระทบระดับแนวทางป้องกัน
D1Neon แพ็กเกจฟรีมีโควตาพื้นที่/ช่วงเวลา restore ย้อนหลังจำกัด ไม่มี SLA — ข้อมูลบัญชีเป็นข้อมูลสำคัญข้อมูลสูญหาย/กู้ย้อนหลังไม่ได้สูงpg_dump ออกไปเก็บภายนอกสม่ำเสมอ (อย่างน้อยรายวัน) · พิจารณาแพ็กเกจเสียเงิน · ซ้อมกู้คืนทุกไตรมาส
D2On-premise: สำรองด้วย backup.sh เก็บในเครื่องเดียวกัน ไม่มี off-site / ไม่มีการเตือนเมื่อสำรองล้มเหลวดิสก์เสีย = ข้อมูลและสำรองหายพร้อมกันสูงคัดลอกไปเครื่อง/คลาวด์อื่น (3-2-1) · ตั้งเตือนเมื่อ cron ล้มเหลว · เข้ารหัสไฟล์สำรอง
D3ยังไม่เคยซ้อมกู้คืนจากไฟล์สำรองบนระบบจริงเป็นขั้นตอนมาตรฐานสำรองใช้ไม่ได้เมื่อจำเป็นสูงซ้อม restore ลงฐานทดสอบและรัน neon_4 + เทียบยอด Trial Balance ตามกำหนด
D4ข้อมูลหลักจากระบบเดิม (APEX) ถูกย้ายครั้งเดียวด้วยสคริปต์ — หากต้องย้ายใหม่ ต้องรันตามลำดับ 01→07 อย่างเคร่งครัดFK ล้มเหลว/ข้อมูลไม่ครบต่ำใช้ลำดับที่ยืนยันแล้วในเอกสาร 05 · เก็บ dump ของฐานที่ผ่านการตรวจแล้วไว้เป็น baseline
D5ไฟล์แนบเก็บในฐานข้อมูล (จำกัด 4 MB/ไฟล์) — ปริมาณมากทำให้ฐานโตเร็วและเกินโควตา Neon ฟรีพื้นที่เต็ม/ช้ากลางจำกัดขนาด/ชนิดไฟล์ · ย้ายไป object storage หากปริมาณเพิ่ม · ตรวจขนาดฐานเป็นระยะ

ความพร้อมใช้งานและ PerformanceAvailability & Performance

รหัสความเสี่ยงผลกระทบระดับแนวทางป้องกัน
A1Vercel Hobby: ฟังก์ชันตัดเวลา 30 วินาที, cold start, และเงื่อนไขห้ามใช้เชิงพาณิชย์ใช้เชิงธุรกิจอาจผิดข้อกำหนด/ระบบช้าตอนเริ่มสูงอัปเกรดเป็น Pro หรือย้ายไป On-premise ก่อนใช้งานเชิงพาณิชย์จริง · ตรวจข้อกำหนดล่าสุดของผู้ให้บริการ
A2Neon auto-suspend: คำขอแรกหลังว่างช้า 3–10 วินาทีผู้ใช้เข้าใจว่าระบบค้างกลางแจ้งผู้ใช้ · ปิด auto-suspend ในแพ็กเกจเสียเงิน · (แอปมี cache/prefetch ลดคำขอซ้ำแล้ว)
A3บริการ AI (Gemini) ตอบ 429/503 ได้บ่อยในช่วงคิวเต็มนำเข้าจากไฟล์ล้มเหลวชั่วคราวกลางระบบ retry 3 ครั้ง + รุ่นสำรอง (GEMINI_FALLBACK_MODEL) · ผู้ใช้กรอกเองได้ · ใช้คีย์เสียเงิน
A4จุดล้มเหลวเดี่ยว: Vercel/Neon ล่ม หรือ On-premise เครื่องเดียว ไม่มี HA/replicaใช้ระบบไม่ได้ระหว่างเหตุขัดข้องกลางกำหนด RTO/RPO · On-prem: streaming replica หรืออย่างน้อยกู้ได้ใน N ชั่วโมงจาก dump · ติดตาม uptime
A5ไม่มีการเฝ้าระวัง (monitoring/alert) ระบบ: ไม่มีแจ้งเตือน error, ช้า, หรือ DB เต็มรู้ปัญหาช้ากลางใช้ /api/health กับ uptime monitor · ตั้งเตือนใน Vercel/Neon · ตรวจ log เป็นระยะ

การ Deploy และกระบวนการDeployment & Process

รหัสความเสี่ยงผลกระทบระดับแนวทางป้องกัน
P1การ deploy ด้วยการอัปโหลดไฟล์ผ่านหน้าเว็บ GitHub ด้วยมือ — อัปโหลดไม่ครบชุด (เช่น index.html ใหม่แต่ server.js เก่า) ทำให้หน้าจอกับ API ไม่ตรงกันฟีเจอร์ใหม่ทำงานผิดพลาดสูงทำรายการไฟล์ที่เปลี่ยนทุกรอบ · ใช้ Git CLI/Pull Request · ตั้ง staging/preview ก่อน production
P2ไม่มี CI และไม่มีชุดทดสอบอัตโนมัติ — ตรวจด้วยการทดสอบมือ/สคริปต์ชั่วคราวข้อผิดพลาดหลุดไป productionสูงเก็บสคริปต์ทดสอบ Playwright/SQL ที่ใช้ตรวจ เข้า repo · เพิ่ม GitHub Actions เบื้องต้น (lint + smoke test)
P3ไม่มีเครื่องมือ migration ของฐานข้อมูล (ใช้สคริปต์เรียงเลข) และชุด db/install_db.sh เดิมล้าสมัยไม่ตรงกับชุด neon_*ติดตั้งใหม่แล้วโครงสร้างไม่ครบ/ผิดเวอร์ชันสูงใช้ชุด neon_1…21 + data_migration ตามเอกสาร 05 · ปรับ/ลบ install_db.sh · เพิ่มตารางบันทึกเวอร์ชันสคริปต์ (schema_version)
P4ตั้ง/แก้ Environment Variable บน Vercel แล้วลืม Redeploy — ค่าใหม่ไม่มีผลAI import/การเชื่อมต่อใช้ค่าเก่ากลางใส่ในรายการ go-live · Redeploy ทุกครั้งหลังแก้ env
P5ความรู้ติดตั้งอยู่กับผู้พัฒนา — การ deploy ใหม่ต้องใช้รหัสผ่าน role 3 ตัว, connection string, คีย์ AI ที่ไม่มีบันทึกกลางDeploy ใหม่ล่าช้า/ผิดพลาดเมื่อผู้ดูแลไม่อยู่สูงเก็บความลับใน password manager ขององค์กร · ใช้เอกสาร 05 เป็น runbook · ซ้อม rebuild จากศูนย์ตามรอบ
P6Dependency เพียง express/pg แต่ไม่มีการอัปเดต/สแกนช่องโหว่ และ Node/PostgreSQL มีรอบ EOLช่องโหว่ที่รู้จักไม่ถูกปิดกลางnpm audit ทุกไตรมาส · อัปเดต Node LTS · วางแผนอัปเกรด PostgreSQL ก่อน EOL

บัญชี ภาษี และกฎหมายAccounting, Tax & Compliance

รหัสความเสี่ยงผลกระทบระดับแนวทางป้องกัน
C1เลขที่เอกสารต่อท้ายด้วยรหัส PK จึงอาจข้ามเลข (เช่น สร้างแล้วยกเลิก) — ใบกำกับภาษี/ใบเสร็จตามกฎหมายต้องเรียงต่อเนื่องผู้สอบบัญชี/สรรพากรตั้งข้อสังเกตสูงยืนยันกับนักบัญชีว่าใช้ช่องเลขใบกำกับที่กรอกเอง หรือเพิ่มตัวรันเลขต่อเนื่องแยกตามประเภท
C2ปิดงวดแล้วเปิดงวดย้อนหลังแก้ได้ (เฉพาะ ADMIN) — แม้มี Audit Log แต่ตัวเลขรายงานภาษีที่ยื่นไปแล้วอาจเปลี่ยนรายงานไม่ตรงกับที่ยื่นกลางจำกัดผู้เป็น ADMIN · เก็บ PDF/CSV รายงานภาษีทุกเดือนที่ยื่น · ขออนุมัติก่อนเปิดงวด
C3การคำนวณ VAT/หัก ณ ที่จ่าย/แบบ ภ.ง.ด. อยู่ในฟังก์ชันที่ผู้พัฒนาเขียนเอง ยังไม่ผ่านการสอบทานโดยผู้สอบบัญชีอิสระยื่นภาษีผิด/ค่าปรับสูงให้นักบัญชี/ผู้สอบบัญชีทดสอบ parallel run 1–2 เดือนเทียบระบบเดิม · เทียบยอดรายงานกับแบบ ภ.พ.30
C4ไม่มีสต็อก/ต้นทุนขาย (COGS) และรายการปรับปรุงสิ้นงวด (ค่าเสื่อม ค้างจ่าย) ในหน้าจองบการเงินไม่ครบสำหรับธุรกิจสินค้ากลางยืนยันขอบเขตธุรกิจ (บริการ/สินค้า) · วางแผนเพิ่มโมดูลหรือบันทึกผ่าน Cash Book
C5ข้อมูลส่วนบุคคลของลูกค้า/ผู้ขาย/พนักงาน (ชื่อ ที่อยู่ เลขผู้เสียภาษี) เก็บในฐานข้อมูล — อยู่ภายใต้ PDPA; ข้อมูลอยู่บน cloud ต่างประเทศ (Neon/Vercel)ละเมิด PDPA หากไม่มีมาตรการ/ข้อตกลงที่เหมาะสมกลางกำหนดผู้ควบคุมข้อมูล · นโยบายความเป็นส่วนตัว · เลือก region ที่เหมาะสม · จำกัดสิทธิ์ตามหน้าที่ · อายุการเก็บข้อมูล
C6การเก็บบันทึกบัญชีต้องเก็บตามกฎหมาย (ปกติ ≥ 5 ปี) — หากฐานข้อมูล/แพ็กเกจถูกยกเลิก ข้อมูลหายไปด้วยขาดหลักฐานทางบัญชีกลางเก็บ dump รายปีแบบถาวรนอกระบบ · ส่งออกรายงานสิ้นปี PDF

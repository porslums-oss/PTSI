ลำดับงานตั้งแต่ใบเสนอราคา → ใบแจ้งหนี้ → รับเงิน และฝั่งซื้อ ใบขอซื้อ → ใบสั่งซื้อ → ใบแจ้งหนี้ผู้ขาย → จ่ายเงิน/หัก ณ ที่จ่าย จนถึงงบทดลองและการปิดงวด

ฝั่งขาย — จากใบเสนอราคาถึงรับเงินOrder-to-Cash

ขั้นตอนบังคับคือ ใบเสนอราคา → ใบแจ้งหนี้ → Post → ใบเสร็จ → Post ส่วนใบส่งของและใบวางบิลเป็นทางเลือก

1. ใบเสนอราคา (Quotation)เมนู Sales → Quotations · ต้องมีสิทธิ์ sales.edit

DRAFT → SENT → ACCEPTED
Q-{หมวด}-{ลำดับ} เช่น Q-SW_DEV-0001customer_idsalesperson_idvalid_untilpayment_term_textรายการ (quotation_items)subtotal / vat / total
เลขที่: รันตามหมวดเอกสาร (ตาราง quotation_categories.next_seq_no) · VAT คำนวณจากชนิด VAT ของสินค้า · แก้ไขได้ตราบที่ยังไม่ถูกใช้ออกใบแจ้งหนี้กติกา: ฟังก์ชันไม่จำกัดลำดับสถานะ (ตั้งสถานะใดก็ได้จากหน้าจอ) แต่การเปลี่ยนเป็น ACCEPTED ทำได้ต่อเมื่อระบุเลขที่/วันที่ใบสั่งซื้อของลูกค้า (customer_po_no / customer_po_date) แล้วเท่านั้น — ไม่เช่นนั้นระบบตอบ PO_REQUIRED

2. ใบส่งของ (Delivery Note)เมนู Sales → Delivery Notes — ไม่บังคับ

DRAFT → DELIVERED / CANCELLED
DN-YYYYMMDD-NNNNNquotation_idรายการ (คัดลอกจากใบเสนอราคาได้)signature_mode
ออกได้เฉพาะจากใบเสนอราคาที่ ACCEPTED · ไม่ลงบัญชี (ระบบนี้ไม่ควบคุมสต็อกสินค้า)

3. ใบแจ้งหนี้ / ใบกำกับภาษี (Invoice)เมนู Sales → Invoices

UNPAID → PARTIAL → PAID / VOID
INV-YYYYMMDD-NNNNNquotation_iddue_datetax_invoice_nopayment_term_textposted_flagvat_amount / total_amount
สร้างจากใบเสนอราคาที่ ACCEPTED (ต้องมีเลข PO ลูกค้า) · วันครบกำหนดคิดจาก setting.invoice_default_due_days (ค่าเริ่มต้น 30 วัน)Post to GL (สิทธิ์ gl.post) → fn_invoice_post ลงบัญชี: Dr ลูกหนี้การค้า (AR_CONTROL) = ยอดรวม · Cr รายได้ (บัญชีรายได้ของสินค้า หรือ DEFAULT_REVENUE) · Cr ภาษีขาย (VAT_OUTPUT)ก่อน Post: แก้ไข/ยกเลิก (void) ได้ · หลัง Post: ยกเลิกตรงๆ ไม่ได้ (ALREADY_POSTED) ต้องออก ใบลดหนี้ · ยกเลิกไม่ได้ถ้ามีใบเสร็จอ้างอิงอยู่

4. ใบวางบิล (Billing Note)เมนู Sales → Billing Notes — ไม่บังคับ

OPEN → CLOSED / CANCELLED
BN-YYYYMMDD-NNNNNcustomer_idรวมหลายใบแจ้งหนี้ (billing_note_items)due_datetotal_amount
รวมใบแจ้งหนี้ ของลูกค้ารายเดียวกัน ที่สถานะ UNPAID/PARTIAL · ใบแจ้งหนี้ใบหนึ่งอยู่ในใบวางบิลที่เปิดอยู่ได้ใบเดียว (DUPLICATE) · เมื่อรับชำระครบทุกใบ ระบบปิดใบวางบิลเป็น CLOSED อัตโนมัติ (trigger fn_receipt_settle)

5. ใบเสร็จรับเงิน (Receipt)เมนู Sales → Receipts

CREDIT_COLLECTION / CASH_SALE
RC-YYYYMMDD-NNNNNsale_typepayment_method (CASH/TRANSFER/CHEQUE/CREDIT_CARD)receipt_applications → ใบแจ้งหนี้ที่ตัดชำระwht_rate → wht_amountcheque_no / bank_name / payment_ref_datenet_amount
CREDIT_COLLECTION = รับชำระตามใบแจ้งหนี้ (เลือกได้หลายใบ ชำระบางส่วนได้) · CASH_SALE = ขายสดออกใบเสร็จทันทีโดยไม่ผ่านใบแจ้งหนี้ (ใช้ receipt_items)กติกา: ใบแจ้งหนี้ต้อง Post to GL แล้ว จึงรับชำระได้ · รับชำระเกินยอดค้างไม่ได้ · ภาษีหัก ณ ที่จ่ายที่ลูกค้าหักให้คำนวณจาก wht_rate (ระบบคำนวณเอง ไม่รับยอดจากหน้าจอ) · ธนาคารเลือกจาก Master Data → BanksPost: Dr เงินสด/ธนาคาร (DEFAULT_CASH) = ยอดสุทธิ + Dr ภาษีหัก ณ ที่จ่ายรอเรียกคืน (WHT_RECEIVABLE) · Cr ลูกหนี้การค้า (CREDIT_COLLECTION) หรือ Cr รายได้+ภาษีขาย (CASH_SALE) · สถานะใบแจ้งหนี้อัปเดตเป็น PARTIAL/PAID อัตโนมัติ · ลบใบเสร็จได้เฉพาะที่ยังไม่ Post

ฝั่งซื้อ — จากใบขอซื้อถึงจ่ายเงินProcure-to-Pay

ใบขอซื้อและใบรับสินค้าเป็นขั้นตอนควบคุมภายใน ส่วนที่กระทบบัญชีคือใบแจ้งหนี้ผู้ขายและการจ่ายเงิน

1. ใบขอซื้อ (Purchase Request)เมนู Purchasing → Purchase Requests · สิทธิ์ purchasing.edit

DRAFT → PENDING → APPROVED / REJECTED → CLOSED
PR-YYYYMMDD-NNNNNrequested_by (พนักงาน)departmentapproved_byรายการ (pr_items) + estimated_price
ลำดับสถานะ: DRAFT → PENDING (ส่งขออนุมัติ) → APPROVED (ต้องระบุผู้อนุมัติ) หรือ REJECTED (กลับไปแก้เป็น DRAFT ได้) → CLOSED (ปิดอัตโนมัติเมื่อออก PO) · แก้ไข/ลบได้เฉพาะ DRAFT

2. ใบสั่งซื้อ (Purchase Order)เมนู Purchasing → Purchase Orders — สร้างจาก PR หรือสร้างตรง

DRAFT → SENT → CONFIRMED → PARTIAL_RECEIVED → RECEIVED / CANCELLED
PO-YYYYMMDD-NNNNNvendor_idpr_id (ว่างได้)delivery_datepayment_term_textรายการ (po_items)vat_amount / total_amount
การเปลี่ยนสถานะเป็นไปตามลำดับ: DRAFT→SENT/CANCELLED · SENT→CONFIRMED/CANCELLED · CONFIRMED→PARTIAL_RECEIVED/RECEIVED/CANCELLED · PARTIAL_RECEIVED→RECEIVED · ยกเลิก PO ที่ออกจาก PR แล้วไม่มี PO อื่นเหลือ → PR กลับเป็น APPROVED

3. ใบรับสินค้า (Goods Receipt)เมนู Purchasing → Goods Receipts

ACTIVE → VOID

4. ใบแจ้งหนี้ผู้ขาย (Vendor Invoice)เมนู Purchasing → Vendor Invoices — แหล่งข้อมูลภาษีซื้อ

เอกสารนี้ใช้เมื่อไรInstall / Setup / Deploy
ใช้ติดตั้ง Smart ER ใหม่บนเซิร์ฟเวอร์ของ รพ. (แต่ละ OS) หรือขึ้นระบบทดสอบบนคลาวด์ (Vercel + Neon) · รวมรายการ software ทั้งหมด, ขั้นตอน, การตรวจสอบหลังติดตั้ง, การอัปเกรด และ rollback

ความสัมพันธ์กับคู่มือเดิม: คู่มือ 05 อธิบายการติดตั้งบน Ubuntu/Rocky/Windows แบบละเอียดพร้อมภาพ และคู่มือ 09 อธิบาย Vercel — เอกสารนี้ รวมศูนย์ และเพิ่มข้อมูลที่ได้จากการ deploy จริงครั้งนี้ (ขั้นตอนผ่าน Neon SQL Editor, ข้อควรระวัง, ปัญหาที่เจอ)
สถานะการทดสอบ: เส้นทางที่ทดสอบจริงในโครงการ = (1) PostgreSQL 16 บน Linux + Node.js 22 รันในสภาพแวดล้อมทดสอบ และ (2) Vercel + Neon (ระบบรันอยู่ ใช้ข้อมูลจำลอง) · คำสั่งสำหรับ RHEL/Oracle Linux, Windows Server, macOS เป็นขั้นตอนมาตรฐานของ software แต่ละตัว ยังไม่เคยรันบนเครื่องจริงในโครงการนี้ ต้องทดสอบบนเครื่อง staging ก่อนเสมอ ป้ายสถานะระบุไว้ในแต่ละหัวข้อ

ลำดับการติดตั้ง (ทุก OS)8 ขั้น เหมือนกันทุกแพลตฟอร์ม

  1. เตรียมเครื่อง — OS, เวลา, firewall, user สำหรับรันแอป (ไม่ใช้ root)
  2. ติดตั้ง PostgreSQL + ปรับ postgresql.conf / pg_hba.conf
  3. สร้างฐานข้อมูล — แก้รหัสผ่าน 5 role ใน 00_create_db.sql แล้วรัน 00 → 01 → 02 → 03 → 04 → 07 → 08 และ 05_smoke_test.sql (ต้องจบด้วย SMOKE TEST PASSED)
  4. ติดตั้ง Node.js + แอป — npm ci --omit=dev, สร้าง .env (chmod 600)
  5. ตั้ง service + nginx (HTTPS)
  6. เปลี่ยนรหัสผ่านผู้ใช้เริ่มต้น, ตั้งชื่อ รพ., hn_source, TV_KEY
  7. เชื่อมอุปกรณ์ — สแกนเนอร์/ปริ้นเตอร์, monitor, Tablet, จอ TV
  8. ทดสอบก่อนใช้งาน + ตั้ง backup
3

คำสั่งตาม OS

Ubuntu 24.04 LTS / Debianเส้นทางหลักที่คู่มือ 05 อธิบายละเอียด ทดสอบแล้ว

bash — เตรียม OS
sudo apt update && sudo apt -y upgrade
sudo timedatectl set-timezone Asia/Bangkok
sudo apt -y install chrony curl gnupg ca-certificates unzip nginx
sudo systemctl enable --now chrony
sudo useradd -r -m -d /opt/smart-er -s /bin/bash smarter
sudo ufw allow 22/tcp && sudo ufw allow 443/tcp
sudo ufw allow from 192.168.10.0/24 to any port 6000 proto tcp   # subnet ของ monitor
sudo ufw enable
bash — PostgreSQL 16 (PGDG) และ Node.js 22
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc https://www.postgresql.org/media/keys/ACCC4CF8.asc
echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" | sudo tee /etc/apt/sources.list.d/pgdg.list
sudo apt update && sudo apt -y install postgresql-16 postgresql-contrib-16
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt -y install nodejs
bash — ฐานข้อมูล แอป และ service
sudo mkdir -p /opt/smart-er && sudo cp -r smart-er-postgresql/* /opt/smart-er/ && sudo chown -R smarter:smarter /opt/smart-er
cd /opt/smart-er/db
sudo -u postgres psql -v ON_ERROR_STOP=1 -f 00_create_db.sql          # แก้รหัสผ่านในไฟล์ก่อน
SKIP_00=1 OWNER_PWD='<รหัส er_owner>' PGHOST=localhost ./install_db.sh   # 01-04, 07, 08 + ตรวจสอบ
sudo -u smarter -i  # แล้ว: cd /opt/smart-er/app && npm ci --omit=dev && cp .env.example .env && chmod 600 .env
sudo cp /opt/smart-er/deploy/smart-er.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now smart-er
sudo cp /opt/smart-er/deploy/nginx-smart-er.conf /etc/nginx/conf.d/smart-er.conf && sudo nginx -t && sudo systemctl reload nginx

RHEL 9 / Rocky 9 / Oracle Linux 9ใช้ dnf แทน apt ยังไม่ได้ทดสอบในโครงการนี้

bash — เตรียม OS และ PostgreSQL 16 (PGDG)
sudo dnf -y install chrony curl unzip nginx firewalld
sudo timedatectl set-timezone Asia/Bangkok && sudo systemctl enable --now chronyd firewalld
sudo dnf -y install https://download.postgresql.org/pub/repos/yum/reporpms/EL-9-x86_64/pgdg-redhat-repo-latest.noarch.rpm
sudo dnf -qy module disable postgresql
sudo dnf -y install postgresql16-server postgresql16-contrib
sudo /usr/pgsql-16/bin/postgresql-16-setup initdb
sudo systemctl enable --now postgresql-16
# Node.js 22
sudo dnf -y module enable nodejs:22 && sudo dnf -y install nodejs   # หรือใช้ repo ของ NodeSource
bash — firewall และ SELinux
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=192.168.10.0/24 port port=6000 protocol=tcp accept'
sudo firewall-cmd --reload
sudo setsebool -P httpd_can_network_connect 1       # ให้ nginx proxy ไป Node:3000
# ไฟล์ config ของ PostgreSQL อยู่ที่ /var/lib/pgsql/16/data/ (postgresql.conf, pg_hba.conf)
ข้อควรระวัง: ถ้า SELinux เป็น enforcing และ Node ฟังพอร์ต 6000 ต้องอนุญาตพอร์ตด้วย (semanage port -a -t http_port_t -p tcp 6000 หรือกำหนด type ที่เหมาะสม) · ขั้นตอน 3–8 ของแผนติดตั้งเหมือน Ubuntu ทุกประการ (path และ systemd unit ใช้ไฟล์เดิม)

Windows Server 2019 / 2022ตามหัวข้อ “ติดตั้งบน Windows Server” ของคู่มือ 05 ยังไม่ได้ทดสอบในโครงการนี้

  1. PostgreSQL: ติดตั้งจาก EDB installer → เปิด SQL Shell (psql) รัน \i 'C:/smart-er/db/00_create_db.sql' ต่อด้วย 01–04, 07, 08 ด้วย user er_owner
  2. Node.js: ติดตั้ง Node.js 22 LTS (MSI) → cd C:\smart-er\app → npm ci --omit=dev → คัดลอก .env.example เป็น .env
  3. Windows Service: ใช้ NSSM — nssm install SmartER "C:\Program Files\nodejs\node.exe" C:\smart-er\app\server.js ตั้ง AppDirectory = C:\smart-er\app
  4. Firewall: New-NetFirewallRule -DisplayName "Smart ER HL7" -Direction Inbound -Protocol TCP -LocalPort 6000 -RemoteAddress 192.168.10.0/24 -Action Allow และพอร์ต 443 (IIS ARR หรือ nginx for Windows เป็น reverse proxy + certificate)
  5. Backup: Task Scheduler เรียก pg_dump -Fc -h localhost -U er_owner -d smart_er -f D:\backup\smart_er_<วันที่>.dump
ตั้ง Time Zone เป็น SE Asia Standard Time และเปิด Windows Time (NTP) ให้เวลาตรงกับ monitor · อย่าลืมสิทธิ์ของ Service Account ให้อ่านโฟลเดอร์แอปอย่างเดียว

Oracle Solaris (SPARC/x86) และ macOSข้อมูลสำหรับตัดสินใจ

OSสถานะหมายเหตุ
Solaris SPARCไม่แนะนำNode.js ไม่มี binary ทางการสำหรับ Solaris SPARC และไม่ได้ทดสอบในโครงการนี้ — ถ้าองค์กรใช้ Solaris เป็นมาตรฐาน แนะนำให้รันแอป+DB บน Linux VM/Zone แยก
macOS (สำหรับพัฒนา)ยังไม่ได้ทดสอบในโครงการนี้brew install postgresql@16 node@22 แล้วรัน 00–08 และ node server.js ได้ตามปกติ — ใช้เพื่อพัฒนา/สาธิตเท่านั้น ไม่ใช่ production

Deploy บน Vercel + Neonสำหรับทดสอบ / สาธิต

Vercel + Neon (ทดสอบ / สาธิต)เส้นทางที่ deploy จริงครั้งนี้ ทดสอบแล้ว

ภาพรวม: หน้าเว็บ (static) + API (serverless Express) อยู่บน Vercel, ฐานข้อมูลอยู่บน Neon PostgreSQL · ขอบเขต: ไม่รวม HL7 listener (Vercel ไม่รับ TCP) และใช้ข้อมูลจำลองเท่านั้น

  1. Neon: สร้าง project (region Singapore) → ได้ฐาน neondb และ role neondb_owner (ไม่ใช่ superuser)
  2. ติดตั้ง schema ด้วย Neon SQL Editor (เมื่อไม่มี psql): เลือกฐาน แล้ววางและรันตามลำดับ db/neon_editor/neon_1_roles_schema.sql → neon_2_functions.sql → neon_3_views_seed.sql — ไฟล์ที่ 1 ตั้งรหัสผ่าน role ต้อง แก้เป็นรหัสผ่านของคุณเองก่อนรัน ใช้ตัวอักษร+ตัวเลขล้วน
  3. เตรียม DATABASE_URL: postgresql://er_app:<รหัส>@<host ที่มี -pooler>/neondb?sslmode=require (ไม่ใส่เครื่องหมายคำพูดครอบรหัส)
  4. GitHub: สร้าง repo (Private) แล้วอัปโหลด เนื้อหาของโฟลเดอร์ app/ (ไม่เอา node_modules และ .env) ที่รากของ repo
  5. Vercel: Add New → Project → Import repo → Application Preset = Express, Root Directory = ./ → ใส่ Environment Variables: DATABASE_URL (และ TV_KEY เป็นค่าสุ่มยาว) → Deploy
  6. ทดสอบ: เปิด https://<โปรเจกต์>.vercel.app/api/health ต้องได้ {"ok":true,"db":…} → เข้าสู่ระบบ → เปลี่ยนรหัสผ่านทุกบัญชี
จุดที่เคยพลาดข้อควรทำ
รหัสผ่านมีอักขระพิเศษ ($ @ : / #) ทำให้ URL/สคริปต์เพี้ยนใช้รหัสผ่านตัวอักษร+ตัวเลขล้วนยาว ≥ 24 ตัว
password authentication failed for user …รหัสใน DATABASE_URL ไม่ตรงกับ role ใน DB → ALTER ROLE er_app PASSWORD … หรือแก้ URL
แก้ Environment Variable แล้วไม่เปลี่ยนผลต้อง Redeploy ทุกครั้ง — ตัวแปรใหม่มีผลกับ deployment ใหม่เท่านั้น; ค่าที่ตั้งเป็น Sensitive อ่านย้อนกลับไม่ได้ ต้องพิมพ์ใหม่
เปิด URL ของ deployment แล้วเจอหน้า Vercel LoginDeployment Protection ล็อก URL แบบ per-deployment — ใช้โดเมน production ของโปรเจกต์ (หรือปิด protection ตามนโยบาย)
จอ TV ขึ้นแถบสีส้ม “ขาดการเชื่อมต่อ”ตั้ง TV_KEY แล้วแต่เปิดจอโดยไม่มี ?key= — เปิดจากเมนู “จอ TV” ในระบบ ซึ่งแนบ key ให้ (ผ่าน /api/tv-link)
Neon ไม่ใช่ superuser สร้าง function แล้ว owner ผิดสคริปต์ทำ GRANT er_owner TO CURRENT_USER …; SET ROLE er_owner; ก่อนสร้าง object (มีใน neon_1 แล้ว)
too many connectionsใช้ host แบบ -pooler ใน DATABASE_URL เสมอ ส่วน migration/psql ใช้ direct host

อัปเกรดและ Rollback

  1. สำรองก่อนเสมอ: pg_dump -Fc ฐานข้อมูล + สำเนา .env และโฟลเดอร์ app/
  2. รันไฟล์ migration ใหม่ด้วย er_owner (-v ON_ERROR_STOP=1) — รันซ้ำได้เฉพาะ 02_functions.sql, 03_views_security.sql และ 07_bed_tablet.sql (ใช้ CREATE OR REPLACE / IF NOT EXISTS) ส่วน 01_schema.sql สร้างตารางตรง ๆ รันซ้ำบนฐานที่มีตารางแล้วไม่ได้ — การเปลี่ยนโครงสร้างตารางต้องเขียนไฟล์ migration (ALTER TABLE) แยกต่างหาก
  3. คัดลอกไฟล์แอปใหม่ แล้ว sudo systemctl restart smart-er (Vercel: push ขึ้น GitHub แล้ว deploy อัตโนมัติ)
  4. ตรวจ /api/health และ smoke test
Rollback: (1) คืนไฟล์แอปเวอร์ชันก่อนหน้าแล้ว restart (Vercel: เลือก deployment เก่า → Promote / Instant Rollback); (2) ถ้า migration ทำข้อมูลเสีย — restore จาก dump ลงฐานทดสอบก่อน ตรวจ แล้วจึงสลับ ห้าม restore ทับฐานจริงทันที; ทดสอบ restore ทุกไตรมาส

Backup & บำรุงรักษา

งานความถี่วิธี
Logical backupทุกวันdeploy/backup.sh (pg_dump -Fc เก็บ 14 วัน) + คัดลอกออกนอกเครื่อง
PITRต่อเนื่องpgBackRest / WAL archiving (แนะนำเมื่อใช้งานจริง)
Partition ล่วงหน้า / ลบของเก่าทุกวัน06_maintenance.sql → fn_create_partitions(3), fn_purge_partitions (cron / Task Scheduler)
ตรวจ HL7 errorทุกวันSELECT parse_status,count(*) FROM er.hl7_message WHERE received_at>now()-interval '1 day' GROUP BY 1;
ทดสอบ restoreทุกไตรมาสcreatedb smart_er_test && pg_restore -d smart_er_test <dump>

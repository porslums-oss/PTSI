เครื่องมือและวิธีการ

กลุ่มเครื่องมือ / เทคโนโลยีใช้ทำอะไร
ฐานข้อมูลPostgreSQL 16 · plpgsql · pgcrypto · pg_trgm · partitioning รายเดือนเก็บข้อมูลและ business logic ทั้งหมด, bcrypt รหัสผ่าน, ค้นหาชื่อ, แบ่ง partition ข้อมูล HL7/สัญญาณชีพ
BackendNode.js 22 · Express 4 · pg 8 (2 dependency)REST API บาง ๆ เรียก SELECT er.fn_*()
FrontendHTML + JavaScript ล้วน (ไม่มี build step) — index.html, tv.html, bed.htmlระบบหลัก, จอ TV, Tablet ประจำเตียง
IntegrationHL7 v2.6 (ORU^R01 / ORU^R40) ผ่าน MLLP — listener เขียนเอง; simulator ทดสอบรับสัญญาณชีพและ alarm จากเครื่อง patient monitor (Northern)
เอกสาร / ผังHTML + CSS ชุดเดียวกัน · Mermaid · Python (สร้าง ERD HTML และ Excel data dictionary จาก catalog)เอกสารชุด 00–11, ER diagram, พจนานุกรมข้อมูล
ทดสอบSQL smoke test (05_smoke_test.sql) · HL7 simulator · Playwright (ภาพหน้าจอ) · npm auditตรวจ logic ใน DB, ตรวจ pipeline HL7, ถ่ายภาพหน้าจอคู่มือ, ตรวจช่องโหว่ dependency
Deploy (ทดสอบ)GitHub (private repo) · Vercel (Express preset, serverless) · Neon PostgreSQL (pooled endpoint) · Neon SQL Editorขึ้นระบบทดสอบบนคลาวด์โดยไม่ต้องมีเซิร์ฟเวอร์
Deploy (production)systemd + nginx + chrony + pg_dump / pgBackRest · NSSM บน Windowsติดตั้งบนเซิร์ฟเวอร์ของ รพ.
ผู้ช่วยClaude (Cowork) — เขียนโค้ด/สคริปต์/เอกสาร และพาทำขั้นตอนบน Neon / GitHub / Vercel ผ่านเบราว์เซอร์ในแอปการกรอกรหัสผ่าน การสร้างทรัพยากรและการยืนยันสิทธิ์ ผู้ใช้ทำเอง

การตัดสินใจเชิงสถาปัตยกรรม

การตัดสินใจเหตุผล
Business logic อยู่ใน PostgreSQL function (ไม่ใช่ใน Node)ตรวจสอบ/ทดสอบได้ที่ DB, หลายระบบเรียกใช้ซ้ำได้, Node เป็นชั้นบาง → ขึ้น serverless ได้โดยไม่แก้ logic
แยก 5 role ตามหน้าที่ (owner / app / hl7 / tv / report) และ SECURITY DEFINERleast privilege — แอปไม่เขียนตารางตรง; จอ TV อ่านได้แค่ 3 view; รายงานอ่านอย่างเดียว
ปกปิด HN บนจอ TV (4 หลักท้าย) ไม่แสดงชื่อ; เรียกคิวด้วยเลข + เตียงลดการเปิดเผยข้อมูลสุขภาพในที่สาธารณะ (PDPA)
Tablet ใช้ device token ที่ผูกกับเตียงใน DB; ล็อกอัตโนมัติ 15 นาทีป้องกันดูข้อมูลผู้ป่วยเตียงอื่น — เตียงถูกกำหนดจาก DB ไม่ใช่จาก client
เก็บสัญญาณชีพ: vital_latest (UPSERT) + vital_sign (ทุก 60 วินาที, partition รายเดือน)เครื่องส่งทุก 1 วินาที — ลดปริมาณข้อมูลและ I/O
fn_next_counter เลขรันรายวันด้วย UPSERTปลอดภัยเมื่อเรียกพร้อมกัน เลขไม่ซ้ำ
Vercel: server.js export app, ไม่ listen เมื่อมีตัวแปร VERCEL; pool เล็ก (3)รองรับ serverless โดยไม่กระทบการติดตั้งแบบเซิร์ฟเวอร์เดิม
TV key ดึงจาก /api/tv-link หลัง loginไม่ฝัง key ไว้ในไฟล์หน้าเว็บ
4

ปัญหาที่เจอและวิธีแก้บทเรียนจากการ deploy จริง

ปัญหาที่เจอสาเหตุวิธีแก้
ไม่มี psql บนเครื่องผู้ใช้ / เซิร์ฟเวอร์ออก TCP ไม่ได้Windows ไม่มี psql; ไม่เชื่อมต่อ Neon จากเครื่องช่วยได้แปลงสคริปต์เป็นชุด 3 ไฟล์สำหรับ Neon SQL Editor (ตัด \set ซึ่งเป็นคำสั่ง psql)
neondb_owner ไม่ใช่ superuserสร้าง object ด้วยสิทธิ์เจ้าของไม่ได้ตรง ๆGRANT er_owner TO CURRENT_USER … ; SET ROLE er_owner ก่อนสร้าง schema/function
รหัสผ่านมี $ ทำให้ URL/เชลล์เพี้ยนการขยายตัวแปรของเชลล์และการ encode URLเปลี่ยนเป็นรหัสผ่านตัวอักษร+ตัวเลข
เปิดเว็บที่ deploy แล้วเจอหน้า Vercel LoginDeployment Protection บน URL per-deploymentใช้โดเมน production ของโปรเจกต์
จอ TV แสดงแถบส้ม “ขาดการเชื่อมต่อ”ตั้ง TV_KEY แต่เปิดจอไม่มี ?key= → API ตอบ 403เพิ่ม /api/tv-link และให้เมนูจอ TV ดึง key หลัง login
password authentication failed for user acct_app (ระบบบัญชี)รหัสใน URL ไม่ตรงกับ role ใน DBตั้งรหัส role ใหม่ให้ตรง แล้ว redeploy
แก้ Environment Variable แล้วไม่เปลี่ยนผลตัวแปรมีผลเฉพาะ deployment ใหม่Redeploy ทุกครั้งที่แก้

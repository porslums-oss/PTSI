ทดสอบ Deploy บน Vercel + PostgreSQL (Neon)

ขึ้นหน้าเว็บ (Main / TV / Tablet) และ REST API บน Vercel โดยใช้ฐานข้อมูล PostgreSQL บนคลาวด์ — เหมาะสำหรับ ทดสอบ/สาธิตด้วยข้อมูลจำลอง · v1.0 · ตุลาคม 2569

ขอบเขต: เวอร์ชันนี้ ยังไม่รวม HL7 listener (TCP/MLLP) เพราะ Vercel รับได้เฉพาะ HTTP — ข้อมูลสัญญาณชีพจากเครื่อง monitor จะยังเข้าไม่ได้ จนกว่าจะวาง listener แยก (ทำภายหลัง) · ส่วนอื่น (ลงทะเบียน, สแกนบาร์โค้ด, triage, Tablet ประจำเตียง, TV board) ใช้งานได้ครบ · ให้ใช้ ข้อมูลจำลองเท่านั้น (PDPA)

1. สถาปัตยกรรม

ผู้ใช้ / TV / Tablet ──HTTPS──▶  Vercel
                                   ├─ Static CDN : /index.html /tv.html /bed.html   (โฟลเดอร์ public/)
                                   └─ Function   : /api/*  → api/index.js → Express (server.js)
                                                         │  pg (pool เล็ก, SSL)
                                                         ▼
                                              Neon PostgreSQL (pooled endpoint)
                                              schema er · 26 tables · 53 functions

Business logic ทั้งหมดยังอยู่ใน PostgreSQL function เหมือนเดิม — Node.js ทำหน้าที่เป็นชั้น API บางๆ จึงรันแบบ serverless ได้โดยไม่ต้องแก้ logic

2. สิ่งที่ปรับในโค้ด (ไม่กระทบการติดตั้งบนเซิร์ฟเวอร์เดิม)

ไฟล์การเปลี่ยนแปลง
app/server.jsถ้ามีตัวแปร VERCEL → ไม่ listen() และไม่เปิด HL7 listener; แล้ว module.exports = app
app/config.jsรองรับ DATABASE_URL (SSL, pool ค่าเริ่มต้น 3 connection)
app/api/index.jsใหม่ — Serverless Function ที่ส่งต่อเข้า Express
app/vercel.jsonใหม่ — rewrite /api/* → function, timeout 15 วินาที, no-store cache
app/.vercelignoreใหม่ — ไม่อัปโหลด .env / tools
db/00_create_roles_neon.sql
db/install_neon.sh		ใหม่ — ติดตั้ง DB บน Neon (ไม่ต้องใช้ superuser/สร้าง database) สุ่มรหัสผ่านทุก role ให้อัตโนมัติ

3. ขั้นตอน Deploy

ขั้นที่ 1 — สร้างฐานข้อมูล Neon

  1. เข้า vercel.com → Storage → Create → Neon (Postgres) (หรือสมัครที่ neon.tech โดยตรง) เลือก region ใกล้ไทย เช่น Singapore (ap-southeast-1)
  2. เปิดหน้า database → Connection details → ปิดสวิตช์ Connection pooling เพื่อดู Direct host (ไม่มี -pooler) พร้อมชื่อ database (ปกติ neondb) และ user/password ของ neondb_owner

ขั้นที่ 2 — ติดตั้ง schema ด้วยสคริปต์

รันจากเครื่องที่มี psql (Linux / macOS / WSL / Git Bash) — ต้องใช้ Direct host เท่านั้น

cd smart-er-postgresql/db
NEON_HOST=ep-xxxxxx.ap-southeast-1.aws.neon.tech \
NEON_DB=neondb \
ADMIN_USER=neondb_owner \
ADMIN_PWD='รหัสผ่าน neondb_owner' \
bash install_neon.sh

สคริปต์จะ: สร้าง role (er_owner, er_app, er_hl7, er_tv, er_report) + extension pgcrypto, pg_trgm → สร้าง schema er → รัน 01–04, 07, 08 → ตรวจจำนวนเตียง (38) → พิมพ์ DATABASE_URL ของ er_app (pooled) ออกหน้าจอ ครั้งเดียว ให้คัดลอกเก็บไว้

ไม่มี psql บน Windows? ใช้ WSL หรือ Git Bash ได้ · หรือเปิด Neon SQL Editor แล้ววางไฟล์ 01_schema.sql … 08_comments.sql ตามลำดับ (ต้องสร้าง role ด้วยมือก่อน)

ขั้นที่ 3 — Push โค้ดและสร้างโปรเจกต์ Vercel

# ตัวเลือก A: Vercel CLI
npm i -g vercel
cd smart-er-postgresql/app
vercel login
vercel                 # ตอบ: Set up and deploy? Y · ไม่ต้องมี build command · output directory: public

# ตัวเลือก B: GitHub
#   push โฟลเดอร์ app/ ขึ้น repo → Vercel Dashboard → Add New → Project → Import
#   Framework Preset = Express (Vercel ตรวจพบอัตโนมัติ) · Root Directory = app (หรือรากของ repo ถ้า push เฉพาะ app)

ขั้นที่ 4 — ตั้ง Environment Variables

ตัวแปรค่าหมายเหตุ
DATABASE_URLpostgresql://er_app:…@ep-xxx-pooler.…neon.tech/neondb?sslmode=requireจากขั้นที่ 2 — ต้องเป็น host ที่มี -pooler
TV_KEYสตริงสุ่มยาว ๆแนะนำมาก — เปิดจอ TV ด้วย /tv.html?key=… หรือกดเมนู “จอ TV” ในระบบ (ระบบแนบ key ให้ผ่าน /api/tv-link หลังล็อกอิน)
PG_POOL_MAX3ไม่บังคับ (ค่าเริ่มต้น 3)
vercel env add DATABASE_URL production
vercel env add TV_KEY production
vercel --prod

ขั้นที่ 5 — ทดสอบ

  1. เปิด https://<โปรเจกต์>.vercel.app/api/health → ต้องได้ {"ok":true,"db":"…"}
  2. เปิดหน้าแรก เข้าสู่ระบบ admin / Admin@12345 → เปลี่ยนรหัสผ่านทันที
  3. ลองสแกน/พิมพ์ HN เพื่อลงทะเบียนผู้ป่วยทดสอบ, เปิด Triage, ดูจอ /tv.html?key=…
  4. เมนู ADMIN → Tablet ประจำเตียง → สร้าง pairing code → เปิด /bed.html บนแท็บเล็ตเพื่อจับคู่

4. ข้อควรระวัง

หัวข้อรายละเอียด
HL7 / monitorยังไม่ทำงานบน Vercel (TCP) · ทดสอบ logic ด้วย POST /api/hl7/test (ADMIN/NURSE) โดยส่งข้อความ HL7 ดิบใน raw ได้ · ของจริงต้องมี listener แยก — ทำเป็นขั้นต่อไป
ข้อมูลจริง / PDPAห้ามใช้ข้อมูลผู้ป่วยจริงบนสภาพแวดล้อมทดสอบนี้ · Vercel/Neon เป็นผู้ให้บริการต่างประเทศ ต้องประเมิน DPIA ก่อนใช้งานจริง
รหัสผ่านseed user (admin / nurse01 / reg01) เป็นรหัสตัวอย่าง ต้องเปลี่ยน · ห้าม commit .env หรือ DATABASE_URL ลง Git
ConnectionAPI ต้องใช้ pooled host เสมอ · migration/psql ใช้ direct host
Cold start / Neon sleepNeon แพ็กเกจฟรีจะหลับเมื่อไม่มีการใช้งาน (คำขอแรกช้า 1–3 วินาที) และ Vercel Function เริ่มเย็น — เป็นเรื่องปกติของการทดสอบ
Polling จอ TV / Tabletหน้า TV และ Tablet ดึงข้อมูลเป็นรอบ แต่ละครั้งนับเป็น 1 function invocation และ 1 query — ถ้าเปิดหลายจอตลอดวันอาจชนโควตาฟรี ให้เพิ่มช่วงเวลา poll ถ้าจำเป็น
Partition รายเดือนไม่มี cron บนเครื่อง — รัน SELECT er.fn_create_partitions(3); ด้วย er_owner เป็นระยะ (หรือตั้ง Vercel Cron เรียก endpoint ภายหลัง) ตอนติดตั้งสร้างล่วงหน้าไว้แล้ว
Regionตั้ง Function Region ให้ใกล้ DB (Singapore sin1) ที่ Settings → Functions เพื่อลด latency

5. แก้ปัญหาเบื้องต้น

อาการสาเหตุ / วิธีแก้
/api/health → 500 / timeoutตรวจ DATABASE_URL (ต้องมี sslmode=require, host แบบ pooler) · ดู Logs ใน Vercel Dashboard
password authentication failed for user "er_app"รหัสผ่านใน URL ผิด/มีอักขระพิเศษไม่ได้ encode — สคริปต์สุ่มเฉพาะตัวอักษร+ตัวเลข ไม่ต้อง encode
permission denied for schema erรัน 03_views_security.sql ไม่สำเร็จ — รัน 03_views_security.sql ซ้ำได้ (ใช้ CREATE OR REPLACE) — แต่ ห้ามรัน 01_schema.sql ซ้ำ บนฐานที่มีตารางแล้ว
หน้าเว็บ 404 ที่ /tv.htmlRoot Directory ของโปรเจกต์ต้องเป็นโฟลเดอร์ที่มี public/ และ vercel.json
/api/... ได้ 404 จาก Vercel (ไม่ใช่ JSON)ไม่พบ api/index.js หรือ vercel.json ไม่ถูก deploy — ตรวจว่าไม่ถูก .vercelignore
too many connectionsใช้ direct host ใน DATABASE_URL โดยไม่ตั้งใจ — เปลี่ยนเป็น -pooler

6. ขั้นต่อไป (ยังไม่ทำ)

รับ HL7 จากเครื่อง monitor จริง: วาง hl7-listener.js บน VM/คอนเทนเนอร์ที่รับ TCP ได้ (Railway, Fly.io หรือเครื่องในโรงพยาบาล) ต่อเข้า Neon ด้วย role er_hl7 (ใช้ direct host) — ฝั่ง DB ไม่ต้องแก้
